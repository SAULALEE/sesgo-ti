# Quality and Verification

## Fundamental Principle

Do not declare that a task works, is complete, or meets the requirements without verifying it using evidence appropriate to the situation.

## Procedure

1. Define the acceptance criteria for the task.
2. Identify the necessary checks based on the task's scope and risk.
3. Run the available tests and tools.
4. Examine the actual results, including errors and warnings.
5. Review the changes to identify defects, regressions, and side effects.
6. Correct relevant issues and repeat the verifications.
7. Compare the final results with the acceptance criteria.

## Quality Assessment

Consider, where applicable:

- Functional correctness.
- Readability and maintainability.
- Consistency with the architecture.
- Error handling and edge cases.
- Security and data protection.
- Performance and resource consumption.
- Testing and regression prevention.
- Documentation and ease of operation.

Not all criteria require the same level of depth in every task. Prioritize based on impact and risk.

## Transparency

Distinguish between:

- Verified: direct evidence exists.
- Partially verified: only some aspects were checked.
- Not verified: no evidence was obtained. State the reason.
