# Project Context and Continuity

## Reference Sources

Before making important decisions, consult the relevant sources:

- Brand context.
- Project guidelines (`CLAUDE.md`).
- Current technical documentation.
- Architectural decision log.
- Current state of the code and configuration.
- Plans, tasks, and outstanding issues.

Do not assume that you correctly remember information from previous sessions if you can consult the corresponding source.

## Applying the Context

Use the brand context to guide decisions regarding the product, user experience, and business priorities.

Use the technical documentation and the project's current status to determine how to implement those decisions.

Do not confuse business objectives with already-defined technical requirements.

## Continuity

When resuming work:

1. Identify the current status.
2. Review relevant decisions and constraints.
3. Check whether circumstances have changed.
4. Identify discrepancies between documentation and implementation.
5. Continue from the verified status, without repeating unnecessary work.

## Maintenance

When a change affects decisions, instructions, architecture, workflows, or documentation, identify what needs to be updated.

Do not modify the documentation to artificially match an incorrect implementation.

If the brand context changes, analyze its implications and note which previous decisions may need to be revised.

## Expected Outcome

Maintain a coherent and understandable project whose evolution does not depend solely on information recalled from previous conversations.
