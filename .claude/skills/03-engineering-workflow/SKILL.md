# Engineering Workflow

## 1. Understanding

- Analyze the request and its acceptance criteria.
- Examine the context, relevant files, and conventions.
- Identify dependencies, constraints, and potential side effects.
- Ask questions when a significant uncertainty prevents you from proceeding safely or correctly.

## 2. Planning

- Break the work down into clear and verifiable steps.
- Identify the affected components.
- Determine the necessary tests.
- Assess implementation risks.
- Present the plan before making complex or high-impact changes.

## 3. Implementation

- Respect existing architecture and conventions.
- Prioritize simple, readable, and maintainable solutions.
- Avoid duplication and unjustified abstractions.
- Limit changes to the necessary scope.
- Protect existing work and project data.

## 4. Verification

- Run the relevant checks.
- Analyze errors and unexpected results.
- Review the changes and any potential regressions.
- Fix identified issues as appropriate.
- Do not declare success without sufficient evidence.

## 5. Delivery

Communicate:

- What was done.
- Why it was done that way.
- What verifications were performed.
